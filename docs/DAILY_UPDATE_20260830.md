## 2. 핵심 수치 브리핑

### 검출 엔진 벤치마크 (합성 표본 40장)

| 지표 | 최초 | **최종** | 개선 |
|---|---:|---:|---|
| 인스턴스 F1 | 0.308 | **0.494** | +60% |
| 재현율 | 0.198 | **0.556** | +181% |
| 균열폭 MAE | 1.004 mm | **0.506 mm** | −50% |
| 균열폭 편향 | +0.949 mm | **−0.122 mm** | 계통오차 제거 |
| 상태등급 일치율 | — | **0.800** | — |

개선은 네 번의 진단으로 이루어졌습니다.

1. **정답 라벨 자체가 틀렸습니다** — 명목 선 두께를 정답으로 썼는데,
   안티에일리어싱·분기 중첩·원근 왜곡 때문에 화소상 실제 폭과 어긋났습니다.
   최종 렌더링 마스크에서 검출기와 **동일한 정의**로 재측정하도록 바꿨습니다.
2. **성장 영역이 선형 제약 없이 퍼졌습니다** — 암부만으로 성장시키니 표면
   얼룩을 타고 화면 전체가 한 덩어리가 되어, 여러 균열이 하나로 병합되고
   폭이 과대평가됐습니다. 능선 응답으로 제약해 해결했습니다.
3. **폭 정의를 바꿨습니다** — 거리변환(이진화 임계 의존) → **법선 방향 밝기
   프로파일의 FWHM**(임계 무관). 여기에 촬영계 PSF를 이차합으로 제거해
   편향 +0.72mm를 −0.12mm까지 줄였습니다.
4. **평가 지표가 틀렸습니다** — bbox IoU로 매칭했는데, 화면을 가로지르는
   균열들은 외접 사각형이 거의 같아 매칭이 무너졌습니다. 선형 구조 평가의
   표준인 **중심선 버퍼 겹침**으로 교체했습니다.

현장 보정이 필요합니다.

**③ 계측 데이터는 전부 시뮬레이션입니다.** 물리 성분(열신축·압밀·버스트)을

학습 파이프라인이 동작함을 보이는 단계입니다.

**⑤ 판정 결과의 법적 지위.** 모든 화면과 판정서에 "책임기술자 검토·서명 필요"를

## 4. n8n 백엔드 전환 설계

수집·스케줄·카탈로그·자동조사를 코드가 아닌 **n8n 워크플로우**로 두는 구조를
설계하고 3종을 작성했습니다.

- `01_data_collection` — 15분 주기 + 웹훅, 파일명 규약에서 촬영 메타 파싱,
  규약 위반은 격리 큐로. 스케일을 모르면 mm 환산이 불가능해 판정이 성립하지 않기 때문입니다.
- `02_admin_agent` — 관리자가 자연어로 백엔드를 조회·수정. n8n 자기수정 API를
  에이전트 도구로 갖습니다. 모든 결정은 감사 로그에 남습니다.
- `03_auto_research` — 주간 자율 조사. 재촬영률·검출 신뢰도·급진행 균열에서
  **모델의 약점을 스스로 찾아** 조사 주제를 만들고, 적용 가능하다고 판단해도
  **사람 승인 대기 상태로만** 제안을 등록합니다.

경계는 명확합니다 — **배관은 스스로 바꿔도, 판정 기준은 사람이 승인합니다.**
